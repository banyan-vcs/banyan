# 15 · 目录级高并发工作流（M4，设计稿）

> 2026-10-25 设计定稿（未实施）。动机是 docs/00 问题链的最后一环：
> **Agent 分钟级并发** vs git 集中式 ref 协作模型（push 锁、CAS 重试、
> rebase 级联）。v5 已把**跨目录**并发降为 O(1)（目录时间线各自 CAS），
> M4 补齐**同目录**并发的正确性与吞吐：提交队列（P2-5）、分歧收敛
> （目录 merge train）、观测与基准门。客户端零协议改动——一切语义在
> 服务端，git push 行为不变。

## 0. 现状与缺口

已有：写路径 = 目录时间线 CAS（跨目录零锁）；内容级 sameXView 守卫
（顺序流正确；分叉流拒绝 non-fast-forward，客户端 pull --rebase 恢复
——T18 已钉住恢复路径）；push 后预热。

缺口（docs/02 §13 开放项 + docs/11 B7/P2-5）：

1. **同目录突发**：N 个客户端同时 push 同一目录 → CAS 竞争 +
   race-window 守卫逐个拒绝 → 客户端重试风暴放大（B7）；
2. **真并发分歧语义**：同秒同基的两份修改，时间线 CAS 保证恰一者
   落地，后到者被遮蔽（last-writer-wins 呈现）——无收敛语义；
3. **treeKnown/批内树集合线性扫描**（10 万提交上限）——收敛判定
   的可扩展性前置。

## 1. 设计原则

- **串行点已有**：refs 服务的 head CAS 是同目录唯一串行点（docs/10
  §1）。队列是它的前置编排，**不新增共识机制**；
- **队列是建议性的**：崩溃/重启即清空，安全性由 CAS 语义兜底——
  队列丢失最多退回今天的"拒绝+重试"行为，绝不产生错误状态；
- **收敛默认自动**：分歧 push 服务端 rebase 到演进中的 tip，冲突才
  显式失败——Agent 不应需要理解人工 rebase 流程；
- **语义在存储层**：这是 banyan 定位的直接兑现（docs/01：协作流程
  归平台，但同目录收敛是存储层时间线语义的自然延伸）。

## 2. 同目录提交队列（P2-5 交付）

- **结构**：refs 服务内 per-timeline FIFO（key = repo+anchor+branch），
  有界（默认 64），进程内存；
- **目录票**：receive-pack 在逐 ref 校验后、CAS 前，经内部 RPC
  `AcquireDirTicket{repo, anchor, branch}` 取票——持票者独占该时间线
  的 CAS 窗口；完成（成败皆可）即释放，下一个自动顶上。无竞争
  （队列为空）时取票即时返回，零开销；
- **等待语义**：同步等待（push 连接保持），上限默认 30s；超时 →
  `ng <ref> directory busy, retry`（客户端按 git 原生退避重试）；
- **队满即拒**：`ng backpressure`，不给洪泛留窗口；
- **崩溃安全**：队列随 refs 进程——refs 重启队列清空，CAS 仍是
  裁判（见原则 2）；
- **HA**：refs 是单写者（docs/10 §4），队列跟随 refs 天然单点正确；
  多写者 refs 属 HA-2。

## 3. 分歧收敛：目录 merge train

- **触发**：持票 push 的 old ≠ 当前视图 tip（分歧），且 repo 收敛
  策略为 auto（**默认 auto**，repo 级可设 reject 保持传统语义）；
- **机制（复用现有件）**：服务端把客户端链在**当前 tip 的 X 视图**上
  重放——与 adoptSubtreePush 同族（ReplaceSubtree），基点取最新 tip
  而非 old。v5 织入的投影/重写机械（T18 冲突恢复路径已证明跨视图
  重写可用）就是重放引擎；收敛是其最直接的复用；
- **merge train 语义**：队列内每票基于**前一票的结果**重放——同目录
  突发 N 个分歧 push 依 FIFO 顺序逐个收敛，形成等价于 CI merge train
  的存储层语义；
- **冲突隔离**：重放产物树与基点树同文件冲突 → 该票 `ng conflict`，
  队列继续（一票失败不阻塞列车）；
- **幂等互证**：重放产物树若 treeKnown（已在链历史）→ no-op 跳过
  （同 §13 折叠期三重去重语义，防重复折叠）；
- **可见性**：push 成功即含收敛结果；后续 fetch 取到重写链（与今天
  rebase 恢复路径一致，T18 已验证客户端链可继续工作）。

## 4. 正确性前置（M4.1）

- **treeKnown 树→提交索引**：内存 LRU + 惰性构建，替代线性扫描，
  撤除 10 万提交上限——收敛判定与织入去重共用；
- 重放机械从织入/恢复路径**抽取为独立函数**（输入：客户端链、基点
  tip、X 视图；输出：重放链或冲突点），M4.1 无行为变化，纯抽取。

## 5. 观测与性能门

| 指标 | 说明 |
|---|---|
| `queue_depth` / `queue_wait_p99` | 队列深度与等待分位 |
| `convergence_rebases` / `convergence_conflicts` | 收敛成功/冲突计数 |
| `cas_retries`（前后对照） | P2-5 的直接收益证据 |

bench 新场景 **agent-burst**：8/32/128 并发同目录 push（混合目录
对照组）；SLO：全部落地（零拒绝）+ p99 wait 界 + 混合目录吞吐不降
（跨目录零干扰回归）。

## 6. 测试计划（docs/13 约定）

| # | 用例 | 防回归点 |
|---|---|---|
| T41 | 8 客户端并发 push 同目录：全部落地、FIFO 有序、零拒绝 | 队列正确性 |
| T42 | 分歧收敛：同基双 push，后到者自动收敛可见；冲突票 ng、后续票继续 | merge train + 冲突隔离 |
| T43 | 队满 backpressure / 超时 busy / refs 重启队列清空后仍正确 | 边界与崩溃安全 |

## 7. 边界（诚实清单）

- **不做跨目录原子多目录 push**：pack 对象一次摄入原子，时间线各自
  CAS——多目录 push 无全局原子性（记录为永久边界）；
- **auto 收敛改写提交 OID**：与投影重写语义一致，但与传统 git 用户
  预期不同——文档显著说明 + repo 级 reject 模式逃生门；
- **同步等待占用连接**：30s 等待上限要求网关/负载均衡超时配置匹配
  （部署注意项，docs/12 部署节登记）；
- **收敛作用于 X 视图内**：跨目录文件移动 = 两个目录各自收敛，无
  全局重放；
- 多写者 refs（HA-2 读写分离形态）时，队列须跟随主写者。

## 8. 实施分片

```
M4.1  treeKnown 索引 + 重放机械抽取（纯重构，无行为变化）
M4.2  目录票 + 队列（只串行化，收敛默认关）——P2-5 交付
M4.3  收敛 auto-rebase + 冲突隔离（默认开，repo 级可关）
M4.4  指标 + agent-burst bench 场景 + SLO 门
```

每片独立提交、独立测试（分层提交约定不变）。

## 9. 为什么是 M4（候选取舍）

| 候选 | 评估 | 时序 |
